# Phase 23 Plan 23-01: Document Fetch Safety and Evidence Storage Foundation

**Created:** 2026-05-01  
**Status:** Ready for execution

## Objective

Create the safe fetch boundary and persistent evidence storage needed before policy-document checks can download certificate-derived URLs. This plan establishes security controls, event/snapshot schemas, and focused validation; it does not implement extraction or worker polling yet.

## Scope

### In Scope

- Generalized monitoring-source safe fetch module for public HTTP/HTTPS document URLs.
- Private/internal address and redirect-target blocking.
- Env-controlled timeout, redirect, byte, and localhost-dev settings.
- `monitoring_source_events` schema/helper functions.
- `document_snapshots` schema/helper functions with bounded raw bytes and provenance.
- Phase 23 validator skeleton wired into `validate-all`.

### Out of Scope

- PDF or HTML text extraction.
- Worker loop integration.
- OCSP polling.
- Reporting UI.
- AI compliance analysis.

## Threat Model

<threat_model>
T-23-01: Certificate-derived URLs are attacker-controlled SSRF inputs. Mitigation: only `http:` and `https:` are accepted, DNS is resolved before every request, private/internal/link-local/multicast/unspecified addresses are blocked, and every redirect target is revalidated before following.

T-23-02: Policy documents can be arbitrarily large. Mitigation: `MONITORING_SOURCE_MAX_DOCUMENT_BYTES` is enforced against both `content-length` and buffered bytes before storage.

T-23-03: Evidence can be overwritten or lost on failure. Mitigation: failed checks record `monitoring_source_events` and never delete or mutate prior `document_snapshots`.

T-23-04: Local development exceptions could leak into production. Mitigation: localhost is blocked by default and only allowed when `MONITORING_SOURCE_ALLOW_LOCALHOST=true`.
</threat_model>

## Must Haves

- Public HTTP/HTTPS document URLs are allowed only after SSRF checks.
- Event and snapshot storage exists before document fetch services write evidence.
- Raw evidence storage is bounded by later fetch limits and represented as raw bytes in Postgres.
- Provenance fields needed for future AI analysis are persisted with snapshots.
