## Review Surface Contract

- Single-certificate import must keep review embedded on the existing import page.
- ZIP import and trust-list-derived candidates must use a dedicated review route after preview, with a shared batch review layout.
- Review state must be loaded from a signed temporary token and revalidated on the server before final save.
- The review UI must never trust client-mutated derived values as final authority.
- Trust-list review must be hybrid: one batch envelope for source metadata and one decision surface per candidate.
- Every reviewable field must be editable before save, including technical fields and administrative metadata.
- Any field that diverges from the original or derived value must reveal a mandatory justification field.
- Final save must return the user to the same review state if server revalidation finds new errors, with the first error highlighted and the row kept expanded.
- Non-accepted outcomes (`ignored`, `rejected`, `duplicate`) must persist decision, reason, and provenance, but must not create active certificates.
- The same decision model, validation rules, and audit behavior must apply across single, ZIP, and trust-list origins.

## Interaction Contract

- Default the review page to a two-column layout on desktop: content-heavy review surface plus a compact summary rail.
- On mobile, collapse the summary rail below the review content and keep the primary save control pinned near the bottom.
- Present decisions as a segmented control or radio group with these states: `accept`, `edit`, `ignore`, `reject`, `duplicate`, `pending`.
- Show the derived/original value next to the edited value so the operator can compare them without opening another view.
- When a value changes, render a visible diff or before/after cue and require justification before enabling save.
- Keep row-level audit metadata visible but compact: source, fingerprint or candidate key, origin type, and token status.
- For ZIP imports, treat the archive as the batch envelope and each certificate as a review row.
- For trust-list imports, treat the source metadata as the batch envelope and each extracted candidate as a child decision row.
- Preserve unsaved edits while moving between rows, tabs, or expanded details.
- Save actions must be disabled while the temporary token is missing, expired, or server revalidation is already failing.
- After save success, route to the resulting certificate detail or import-run history with a concise success summary.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Save review |
| Empty state heading | No candidates to review |
| Empty state body | Upload a single certificate, ZIP archive, or trust-list source to generate review items. |
| Error state | The server found new validation problems. Fix the highlighted fields and try saving again. |
| Destructive confirmation | Reject candidate: This item will not create an active certificate. Add a reason so the audit trail records why it was rejected. |

Additional state copy:
- Ignore candidate: This item will be skipped and recorded only in audit history.
- Mark duplicate: This item will not create an active certificate and must reference the matching record or reason.
- Pending review: This item still needs a decision before final save.
