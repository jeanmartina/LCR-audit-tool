## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline micro gaps, compact badges |
| sm | 8px | Label/input inner spacing, chip spacing |
| md | 16px | Default card/control spacing |
| lg | 24px | Section spacing and panel rhythm |
| xl | 32px | Page section separation |
| 2xl | 48px | Major dashboard block separation |
| 3xl | 64px | Page-level macro separation |

Exceptions: minimum interactive hit area 44px height for icon-only and compact action controls.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f8fafc` (light) / `#0f172a` (dark) | Global background and page canvas |
| Secondary (30%) | `#ffffff` (light) / `#1e293b` (dark) | Panels, cards, summary blocks, tables |
| Accent (10%) | `#2563eb` | Primary CTA, selected filter chips/tabs, key navigation actions |
| Destructive | `#ef4444` | Destructive status/error-only indicators and destructive confirmations |

Accent reserved for: primary dashboard actions, active mode/tab chips, active filter chips, and “open executive/export” emphasis controls only.

---

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Open Executive Summary |
| Empty state heading | No reporting data for the selected filters |
| Empty state body | Expand the date range or clear one or more filters, then run the view again. |
| Error state | We could not load this reporting view. Reload the page; if the problem persists, check authentication/session and selected filters. |
| Destructive confirmation | none in this phase scope |

## shadcn Migration Notes

1. Target adoption window: before Phase 33 (`UI-07`) to avoid reworking global consistency twice.
2. Recommended initial set after `components.json` exists: `button`, `badge`, `card`, `table`, `tabs`, `select`, `input`, `tooltip`, `accordion`.
3. Migration sequence: map existing CSS vars in `src/app/layout.tsx` to shadcn semantic tokens, then replace reporting action controls/chips first, followed by filter forms and table shells.
4. Safety: keep third-party registries disabled by default; if enabled later, each block must pass `npx shadcn view` vetting before inclusion.
5. Non-blocking constraint: current Phase 31 implementation remains valid with in-repo primitives and does not require shadcn to satisfy `UI-05`.
