# Phase 24 Plan 24-02: OCSP Request Generation, Issuer Context, and Check Service

**Created:** 2026-05-04  
**Status:** Ready for execution

## Objective

Implement the OCSP technical check service: locate issuer context, generate a DER OCSP request, POST it safely to the responder, store bounded evidence, and record technical-only events.

## Scope

### In Scope

- Install OCSP request/response dependencies.
- Parse certificates into PKIjs objects.
- Resolve issuer certificate context from existing inventory.
- Generate real DER OCSP requests with `hashAlgorithm: "SHA-256"`.
- POST OCSP requests with SSRF-safe fetch behavior.
- Store evidence and events through Plan 24-01 helpers.
- Extend validator for service behavior and semantic-boundary checks.

### Out of Scope

- Full signature/status/freshness validation.
- Worker scheduling.
- UI/reporting changes.

## Threat Model

<threat_model>
T-24-03: OCSP requests without issuer context are malformed or misleading. Mitigation: require matched issuer certificate context and record `not_checkable` with `issuer-certificate-not-found` if unavailable.

T-24-04: Certificate-derived OCSP URLs can target private/internal networks. Mitigation: use the Phase 23 public-target validation before every request and redirect.

T-24-05: Parseable OCSP response data can be misrepresented as revocation validation. Mitigation: store parse metadata only and keep event statuses technical-only.
</threat_model>

<task id="24-02-T3" title="Implement issuer context and OCSP check service">

  <action>
    Create `src/monitoring-sources/ocsp.ts`.

    Export `checkOcspSource(source: MonitoringSourceRecord): Promise<{ eventId: string; evidenceId: string | null; status: OcspCheckEventStatus; responseSha256: string | null }>`.

    Add helpers inside the module:
    - `configurePkijsEngine(): void` using `webcrypto` from `node:crypto` and `pkijs.setEngine` if PKIjs requires explicit engine setup.
    - `parsePkijsCertificate(pemText: string): pkijs.Certificate` using `asn1js.fromBER` and `new pkijs.Certificate({ schema })`.
    - `findIssuerContextForSource(source: MonitoringSourceRecord): Promise<{ certificate: CertificateRecord; issuer: CertificateRecord } | null>`.
    - `buildOcspRequestDer(certificatePem: string, issuerPem: string): Promise<Buffer>`.
    - `parseOcspResponseMetadata(body: Buffer): { parseStatus: "parsed" | "failed"; parseFailureReason: string | null; metadataJson: Record<string, unknown> }`.

    Issuer lookup behavior:
    - Load the target certificate with `findCertificateById(source.certificateId)`.
    - Load all certificates with `listCertificateRecords()`.
    - Convert target and candidate issuer PEMs to `X509Certificate` from `node:crypto`.
    - Select the first candidate where `candidateX509.subject === targetX509.issuer` and `candidateX509.checkIssued(targetX509)` returns true.
    - If no target certificate exists, record `not_checkable` with `failureReason: "certificate-not-found"`.
    - If no issuer certificate matches, record `not_checkable` with `failureReason: "issuer-certificate-not-found"`.

    Check behavior:
    - If `source.sourceType !== "ocsp"`, record `not_checkable` with `failureReason: "source-not-ocsp"`.
    - If `source.state !== "discovered"` or `source.sourceUrl` is null, record `not_checkable` with `failureReason: "ocsp-source-not-discovered"`.
    - Generate DER OCSP request with PKIjs and `hashAlgorithm: "SHA-256"`.
    - POST via `fetchOcspResponseBytes(source.sourceUrl, requestDer)`.
    - Compute SHA-256 for request and response bytes.
    - Store evidence through `recordOcspResponseEvidence`.
    - Record `available` only when HTTP response succeeds, response is within byte limit, and parse status is `parsed`.
    - Record `malformed` when fetch succeeds but OCSP response parsing fails.
    - Record `blocked` for `ocsp-url-private-address-blocked` or invalid scheme.
    - Record `oversized` for `ocsp-response-too-large`.
    - Record `unavailable` for other fetch failures.
    - Never set event status to `good`, `revoked`, or `unknown`.
  </action>
