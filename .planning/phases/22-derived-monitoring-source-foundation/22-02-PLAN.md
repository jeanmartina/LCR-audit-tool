# Phase 22 Plan 22-02: X.509 Extension Parser and Source Derivation

**Created:** 2026-04-28  
**Status:** Ready for execution

## Objective

Evaluate and add a build-safe X.509/ASN.1 parsing dependency, then implement derivation of OCSP and policy-document source candidates from certificate metadata without fetching any derived URLs.

## Scope

### In Scope

- Evaluate `@peculiar/x509`, `pkijs`, `asn1js`, and `@peculiar/asn1-x509` package versions before installing.
- Install the smallest dependency set that supports reliable AIA OCSP and CPS URI extraction.
- Add `deriveMonitoringSourceCandidatesFromCertificate()`.
- Derive OCSP candidates from AIA `id-ad-ocsp` when present.
- Derive CPS/document candidates from Certificate Policies CPS URI qualifiers when present.
- Emit `not_discovered`/`not_checkable` candidates instead of failing on absent or insufficient metadata.

### Out of Scope

- OCSP request construction or polling.
- Document fetching.
- Import/trust-list call-site integration.

## Canonical References

- `.planning/phases/22-derived-monitoring-source-foundation/22-CONTEXT.md`
- `.planning/phases/22-derived-monitoring-source-foundation/22-RESEARCH.md`
- `src/monitoring-sources/types.ts`
- `src/monitoring-sources/model.ts`
- `src/inventory/certificate-admin.ts`

## Threat Model

- Certificate bytes and extensions are untrusted input.
- Parser errors must produce safe derivation states, not crash imports.
- Derived URLs must be stored only; no fetch/poll behavior belongs in this phase.
- Dependency selection must not break Docker/Next.js build or introduce host tooling.

<task id="22-02-T2" title="Implement certificate extension derivation module">
  <read_first>
    - `src/monitoring-sources/types.ts`
    - `src/monitoring-sources/model.ts`
    - `src/inventory/certificate-admin.ts`
    - `.planning/phases/22-derived-monitoring-source-foundation/22-CONTEXT.md`
  </read_first>
  <action>
    Create `src/monitoring-sources/derive.ts`.

    Export `deriveMonitoringSourceCandidatesFromCertificate(input)` with this concrete input shape:
    - `certificateId: string`
    - `fingerprint: string`
    - `pemText: string`
    - optional trust-list provenance: `trustListSourceId`, `trustListSnapshotId`, `trustListRunId`

    Return an array of `MonitoringSourceProvenanceInput` values.

    Required derivation behavior:
    - derive `sourceType: "ocsp"` candidates from AIA OCSP URLs with `documentRole: null`, `policyOid: null`, `state: "discovered"`, `derivationReason: "aia-ocsp"`.
    - derive `sourceType: "policy-document"` candidates from CPS URI qualifiers with `documentRole: "cps"`, the associated policy OID when available, `state: "discovered"`, `derivationReason: "certificate-policies-cps-uri"`.
    - when no OCSP URL exists, include a `not_discovered` OCSP candidate with `sourceUrl: null`, `normalizedUrl: null`, and `derivationReason: "aia-ocsp-missing"`.
    - when no CPS/document URL exists, include a `not_discovered` policy-document candidate with `documentRole: "unknown-policy-document"` and `derivationReason: "policy-document-url-missing"`.
    - when parsing fails, return `not_checkable` candidates with `derivationReason` beginning `certificate-extension-parse-failed:`.
  </action>
  <acceptance_criteria>

    - `src/monitoring-sources/derive.ts` contains `aia-ocsp`.
    - `src/monitoring-sources/derive.ts` contains `certificate-policies-cps-uri`.
    - `src/monitoring-sources/derive.ts` contains `aia-ocsp-missing`.
    - `src/monitoring-sources/derive.ts` contains `policy-document-url-missing`.

    - `src/monitoring-sources/derive.ts` does not contain `fetch(`.
  </acceptance_criteria>
