# Phase 22 Plan 22-01: Monitoring Source Storage and Identity Model

**Created:** 2026-04-28  
**Status:** Ready for execution

## Objective

Create the persistent derived monitoring-source model with explicit lifecycle states, fingerprint-based deduplication, and rich inline provenance. This plan does not parse certificates or integrate import call sites; it establishes the model that later plans use.

## Scope

### In Scope

- Add derived monitoring-source TypeScript types.
- Add deterministic source-key construction.
- Add `monitoring_sources` runtime schema and persistence helpers.
- Add lifecycle states: `discovered`, `not_discovered`, `not_checkable`, `disabled`.
- Store rich inline provenance fields selected in Phase 22 context.
- Add the focused Phase 22 validator skeleton and wire it into `validate-all`.

### Out of Scope

- X.509 extension parsing.
- Certificate/trust-list import integration.
- OCSP polling or document fetching.
- Reporting UI.

## Threat Model

- Duplicate derived sources would corrupt future evidence and reporting.
- Absence of a source must be explicit enough for audit; silent absence loses evidence.
- Provenance must not become a separate ACL model; visibility remains inherited from the parent certificate.
- This phase must not fetch certificate-derived URLs.
