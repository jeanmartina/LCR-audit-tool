<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> public routes | Untrusted query params, locale selection, and rendered public copy cross into server-rendered UI. |
| Public shell -> auth endpoints | Login submissions and provider entry links cross from the public shell into authentication flows. |
| Deployment config -> public provider list | Environment-driven provider enablement determines what appears publicly. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-01 | I | `src/components/public-shell.tsx` and `src/i18n/index.ts` | mitigate | Render copy through the existing translation helpers, keep all public labels as React text, and do not surface callback URLs or provider verification state in the shell. |
| T-27-02 | T | `src/app/auth/page.tsx` and `src/app/page.tsx` | mitigate | Preserve the server-side redirect to `/reporting` for authenticated principals and keep login/form actions on same-origin App Router routes only. |
| T-27-03 | I | `src/auth/providers.ts` and route rendering | mitigate | Filter public provider data to `enabled === true` before rendering, so disabled providers and deployment diagnostics stay out of public login choices. |
| T-27-04 | D | Public shell navigation and locale control | accept | The shell may expose a small amount of public UI state by design; this is a low-risk availability surface and does not change auth or data boundaries. |
</threat_model>
