<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> same-origin group/invite routes | Untrusted form payloads can mutate group membership and invite state. |
| settings tab UI -> audit/history data | Administrative records must be rendered as text, not executable markup. |
| group deletion -> runtime store | Deleting a group must clean up related records atomically so orphaned access data cannot linger. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-04 | E | `src/app/api/auth/groups/[groupId]/route.ts` | mitigate | Keep the group mutation routes behind `assertPermission("members.manage", groupId)` and same-origin checks so a non-member cannot escalate into group administration. |
| T-28-05 | I | `src/app/settings/sections/invites-tab.tsx` | mitigate | Render invite metadata and codes as text-only values and trim all submitted email/slug inputs before persistence. |
| T-28-06 | D | `src/storage/runtime-store.ts` | mitigate | Delete memberships and invites together with the group record so the tab cannot leave orphaned records that confuse later authorization checks. |
</threat_model>
